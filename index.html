§ 1 — Executive Summary
Overview & Objectives
1
This document describes the secure network architecture for a mid-sized organization (~100 employees) operating a hybrid cloud/on-premises environment. The design implements defense-in-depth through layered firewalls, network segmentation, VPN connectivity, and centralized monitoring — protecting an internet-facing web application alongside internal HR and Finance systems.
§ 2 — Network Topology
Physical & Logical Layout
2
Traffic enters through an external firewall/IPS and branches three ways: public requests reach the DMZ only; internal users pass a second firewall to the core switch and their VLAN (20 Internal, 30 Restricted, 40 Mgmt, 50 Guest); cloud traffic is tunnelled via IPSec VPN to AWS VPC.
§ 3 — Security Zones & Trust
Zone Trust Model
3
Zero-trust between zones: all inter-zone traffic denied by default. Restricted Network (VLAN 30) requires MFA and role authorization. Guest Network (VLAN 50) is fully isolated — internet-only via captive portal, no path to any internal segment.
§ 4 — Threats & Risks
Risk Register Overview
4
Key identified threats: external intrusion, phishing, lateral movement, ransomware, data exfiltration, and unauthorized cloud access. Each is assessed for likelihood and impact, then mapped to one or more mitigating controls (see Part 5 — Threat Matrix).
§ 5 — Controls & Mitigations
Security Control Summary
5
Eight controls deployed in layers: Perimeter Firewall, IDS/IPS, VLAN Segmentation, VPN, ACLs, MFA, RBAC, and SIEM. Layered so that failure of any single control does not result in a full breach — defense-in-depth principle.

§ 6 — Assumptions & Limitations

AssumedThe organization uses Active Directory (or equivalent LDAP) for identity management.
AssumedAll endpoints run an organization-managed OS image with up-to-date patches.
AssumedCloud workloads are hosted on AWS; architecture adapts to GCP/Azure with minor changes.
AssumedPhysical cabling and hardware procurement is handled separately by IT operations.
CaveatFirewall rule tuning requires a live traffic baseline — default rules are conservative until then.
CaveatSIEM alert tuning will produce false positives initially; a 2-week baselining period is expected.
Out of ScopeNo penetration testing or active exploitation is performed as part of this project.
Out of ScopePhysical security controls (badge access, CCTV, server room locks) are excluded.
