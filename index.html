Part 3

Network Security Architecture Document

Formal documentation mirroring enterprise "living documentation" standards, covering all required sections for a production-grade security architecture.

§ 1 — Executive Summary
Overview & Objectives
This document describes the secure network architecture for a mid-sized organization (~100 employees) operating a hybrid cloud/on-premises environment. The design implements defense-in-depth through layered firewalls, network segmentation, VPN connectivity, and centralized monitoring — protecting an internet-facing web application alongside internal HR and Finance systems.
§ 2 — Network Topology
Physical & Logical Layout
Traffic enters through an external firewall/IPS, reaches the DMZ (Web/Reverse Proxy), then passes a second internal firewall to reach the core switch. The core switch routes tagged VLAN traffic to four segments: Internal (VLAN 20), Restricted (VLAN 30), Management (VLAN 40), and Guest (VLAN 50). A VPN gateway connects on-prem to AWS VPC via an IPSec tunnel.
§ 3 — Security Zones & Trust
Zone Trust Model
Zero-trust model applied between zones: all inter-zone traffic is denied by default. The Restricted Network (VLAN 30) carries the highest trust requirement — only role-authorized users may access it after MFA. The Guest Network (VLAN 50) is fully isolated, routing internet-only through a captive portal with no path to internal segments.
§ 5 — Controls & Mitigations
Security Control Summary
Eight security controls are deployed in combination: Perimeter Firewall, IDS/IPS, VLAN Segmentation, VPN, ACLs, MFA, RBAC, and SIEM. Each addresses one or more identified risks. Controls are layered so that failure of a single control does not result in a full breach — a principle of defense-in-depth.
§ 6 — Assumptions & Limitations
Scope Boundaries
This architecture assumes no actual production deployment is performed. Packet Tracer or Draw.io diagrams serve as simulation artifacts. Physical hardware selection (specific firewall model, switch SKU) is out of scope. Penetration testing and active exploit validation are excluded per project requirements.
§ 4 — Threats & Risks
Risk Register Overview
Key identified threats include external intrusion, phishing attacks, lateral movement post-breach, ransomware, data exfiltration, and unauthorized cloud access. Each threat is assessed for likelihood and impact, then mapped to one or more mitigating security controls deployed within the architecture (see Part 5 — Threat Matrix).
§ 6 — Assumptions & Limitations (Detail)
+The organization uses Active Directory (or equivalent LDAP) for identity management.
+All endpoints run an organization-managed OS image with up-to-date patches.
+Cloud workloads are hosted on AWS; architecture adapts to GCP/Azure with minor changes.
+Physical cabling and hardware procurement is handled separately by IT operations.
~Actual firewall rule tuning requires live traffic baseline — default rules are conservative.
~SIEM alert tuning will generate false positives initially; a 2-week baselining period is expected.
—No penetration testing or active exploitation is performed as part of this project.
—Physical security controls (badge access, CCTV, server room locks) are out of scope.
